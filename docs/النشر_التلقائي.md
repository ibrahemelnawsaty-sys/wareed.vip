# النشر التلقائي — لا رفع يدوي بعد اليوم

كل دفع إلى الفرع `main` يرفع الملفات المتغيّرة إلى الاستضافة تلقائياً
عبر `.github/workflows/deploy.yml`.

## الإعداد لمرة واحدة (5 دقائق)

### 1) أنشئ حساب FTP في Hostinger
لوحة hPanel ← **Files ← FTP Accounts**. انسخ منها:

| القيمة | مكانها |
|---|---|
| FTP hostname | مثل `ftp.wareed.vip` |
| FTP username | اسم المستخدم |
| FTP password | إن نسيتها اضغط **Change FTP password** |
| مجلد الموقع | غالباً `/public_html/` |

### 2) أضف الأسرار في GitHub
المستودع ← **Settings ← Secrets and variables ← Actions ← New repository secret**:

| الاسم | القيمة |
|---|---|
| `FTP_SERVER` | خادم FTP |
| `FTP_USERNAME` | اسم المستخدم |
| `FTP_PASSWORD` | كلمة المرور |
| `FTP_DIR` | *(اختياري)* مجلد الموقع، الافتراضي `/public_html/` |

> الأسرار مشفّرة داخل GitHub ولا تظهر في السجلات ولا يراها أحد غيرك.

### 3) شغّل أول نشر
تبويب **Actions ← نشر إلى الاستضافة ← Run workflow**.
أول تشغيل يرفع كل الملفات ثم ينشئ سجلاً على السيرفر
(`.ftp-deploy-sync-state.json`)، وبعده يرفع المتغيّر فقط — ثوانٍ معدودة.

## ما لا يلمسه النشر أبداً

`vendor/` · `.env` · `storage/` · `bootstrap/cache/` · ملفات SQLite ·
`node_modules/` — ملفات سيرفر خالصة، لا تُرفع ولا تُحذف.

## ملاحظات

- **قوالب Blade**: تُعاد ترجمتها تلقائياً عند تغيّر الملف — لا إجراء مطلوب.
- **كاش المسارات**: إن كنت شغّلت `route:cache` أو `config:cache` سابقاً،
  احذف ملفات `bootstrap/cache/*.php` مرة واحدة، أو شغّل `php artisan optimize:clear`.
- **حزمة جديدة في composer**: النشر لا يرفع `vendor/`. عند إضافة حزمة
  يلزم `composer install` على السيرفر (SSH)، أو رفع `vendor/` يدوياً مرة واحدة.
  المشروع حالياً لا يحتاج ذلك.
- **بديل أبسط إن كانت خطتك تدعمه**: hPanel ← **Advanced ← GIT**، اربط المستودع
  واضغط Deploy (أو فعّل Auto Deployment بإضافة الـ webhook في GitHub).
  في هذه الحالة يمكنك تعطيل هذا الـ workflow.

## حذف طلب تجريبي من قاعدة البيانات

لا حاجة لفتح قاعدة البيانات:
- **لوحة التحكم** ← متابعة طلبات المتاجر ← زر **حذف** (يعيد فتح الرابط المخصّص).
- أو من الطرفية: `php artisan quote:reset hajar-salama`
